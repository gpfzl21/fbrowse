# fbrowse

[GitHub 소스](https://github.com/gpfzl21/fbrowse) · [npm 패키지](https://www.npmjs.com/package/@wlalsrne/fbrowse) · [MIT 라이선스](LICENSE.md)

Linux 서버의 프로젝트 파일과 선택한 디스크 폴더를 한 창에서 탐색하는 파일 브라우저입니다.
Orca 같은 도구로 원격 서버를 사용할 때 큰 PDF나 파일이 기본 미리보기에서 잘 열리지 않는 문제를
해결하기 위해 만들었습니다. 서버에서 파일을 HTTP로 제공하고 Orca의 내부 브라우저에서 직접 열어
탐색·미리보기할 수 있습니다. 큰 PDF는 HTTP Range로 필요한 부분을 나누어 읽습니다.

텍스트·코드·LaTeX는 원문 보기에서 바로 편집하고 저장할 수 있습니다. Markdown·HTML은 같은 수정 내용을
원문과 미리보기로 전환하며, Git 패널에서 직접 선택한 스테이징·커밋·push 작업도 실행할 수 있습니다.
**Node.js 22.12 이상**에서 실행합니다. Python, Bash 실행기, tmux, flock은 필요하지 않습니다.

## 설치

Node.js와 npm이 설치된 Linux 서버에서 사용자 계정에 한 번 설치합니다.

```bash
npm install --global @wlalsrne/fbrowse
cd /path/to/project
fbrowse
```

설치 명령의 패키지 이름은 `@wlalsrne/fbrowse`, 실행 명령은 `fbrowse`입니다.
프로젝트마다 앱을 복사하거나 `npm install`을 실행할 필요가 없습니다. 실행할 때의 현재 디렉터리가
기본 프로젝트 루트가 됩니다. 앱과 설정 파일을 프로젝트 안에 생성하지 않습니다.
공개 패키지는 설치할 때 npm 로그인이 필요하지 않습니다. Linux, Node.js 22.12 이상이 필요합니다.

npm 전역 경로를 사용자 디렉터리로 지정할 수도 있습니다.

```bash
npm install --global --prefix "$HOME/.local" @wlalsrne/fbrowse
export PATH="$HOME/.local/bin:$PATH"
```

소스에서 설치용 압축을 만드는 경우:

```bash
git clone https://github.com/gpfzl21/fbrowse.git
cd fbrowse
npm ci
mkdir -p dist
npm pack --pack-destination dist
npm install --global ./dist/wlalsrne-fbrowse-0.9.1.tgz
```

로컬 개발용 이름 `@fbrowse/cli`로 설치한 이전 버전을 사용 중이면 같은 prefix에서 이전 패키지를
제거한 뒤 새 이름으로 설치하세요. 루트 설정과 프로젝트 파일은 그대로 유지됩니다.

```bash
npm uninstall --global --prefix "$HOME/.local" @fbrowse/cli
npm install --global --prefix "$HOME/.local" @wlalsrne/fbrowse
fbrowse restart /path/to/project
```

기존에 다른 `fbrowse` 명령이 있으면 먼저 소유권과 위치를 확인하세요. 무관한 명령에 `--force`로
덮어쓰지 마세요.

## 실행과 종료

```bash
fbrowse                        # 현재 프로젝트에서 시작하거나 기존 서버 재사용
fbrowse /path/to/project        # 다른 프로젝트 시작
fbrowse url                    # 현재 프로젝트의 HTTP 주소
fbrowse list                   # 실행 중인 Node 서버 목록
fbrowse logs                   # 현재 프로젝트의 최근 로그
fbrowse stop                   # 현재 프로젝트만 종료
fbrowse restart                # 확인된 기존 포트를 유지하여 재시작
fbrowse --no-pdfjs              # PDF.js 준비 없이 시작
fbrowse --version
fbrowse help
```

서버는 터미널과 분리된 Node 프로세스로 실행합니다. tmux에 접속하거나 터미널을 계속 열어둘 필요가
없습니다. 재부팅 시 자동으로 시작하는 서비스는 설치하지 않습니다. 같은 프로젝트에서는 서버를
재사용하고 다른 프로젝트는 별도 포트로 실행합니다. 종료는 루트·인스턴스 식별과 인증된 HTTP 요청으로
처리하며, 상태 파일에 적힌 PID만 믿고 다른 프로세스를 종료하지 않습니다.

**브라우저 자동 열기는 하지 않습니다.** 표시된 HTTP 주소를 Orca Browser에서 직접 엽니다.
Orca는 선택한 브라우저 환경이며 앱의 런타임 의존성은 아닙니다. 원격 Linux 서버의 `127.0.0.1`은
Windows PC의 localhost와 다릅니다. 외부 Chrome으로 접속하려면 별도의 연결 경로가 필요합니다.

## 여러 루트 폴더 연결

왼쪽 **루트 관리 → 폴더 찾아 연결…**에서 서버의 폴더를 보며 선택합니다.

- 프로젝트·홈·`/mnt`·`/media` 바로가기, 상위 폴더, 경로 탐색줄과 직접 경로 이동
- 내부 폴더와 참고용 파일 이름, 이름 필터와 숨김 표시
- **이 폴더 연결**로 이름·경로 저장 후 해당 루트로 전환
- 등록한 이름·경로 수정, 연결 제거, 끊긴 경로 표시

예를 들어 프로젝트 `/home/user/project`, 논문 `/mnt/data/papers`, 실험결과 `/mnt/archive/results`를
연결할 수 있습니다. 서버에 이미 존재하는 폴더만 새로 연결할 수 있으며 마운트 작업이나 파일
이동·삭제·업로드·동기화는 수행하지 않습니다. 경로가 사라지면 연결 안 됨으로 표시합니다.
디렉터리로 남아 있는 빈 마운트 지점의 마운트 여부까지 자동 판별하지는 않습니다.

```bash
fbrowse roots add papers /mnt/data/papers --name 논문
fbrowse roots edit papers /mnt/new/papers --name 참고논문
fbrowse roots list
fbrowse roots remove papers
fbrowse roots list --project /path/to/other/project
```

등록 정보는 프로젝트별로 `$XDG_CONFIG_HOME/fbrowse/projects/<경로 해시>.json`
(기본 `~/.config/fbrowse/...`)에 기억됩니다. 기존 Python 버전과 설정 형식·위치를 공유합니다.
검색과 미리보기 링크에 root ID와 상대 경로를 사용하므로 같은 이름의 파일도 구분됩니다.
검색은 선택한 루트의 하위 폴더를 대상으로 합니다. 폴더 선택기로 둘러보는 것만으로는 루트가
등록되거나 해당 위치의 파일 내용에 접근할 수 있게 되지 않습니다.

## 미리보기

파일 트리·검색 결과·폴더 선택기에서는 작은 SVG 아이콘으로 폴더와 파일 형식을 구분합니다.
폴더를 펼치면 열린 폴더 모양으로 바뀌며, 파일명과 Git 상태·심볼릭 링크 표시는 함께 유지됩니다.
아이콘은 앱에 내장되어 별도 글꼴이나 네트워크 다운로드가 필요하지 않습니다.

PDF.js의 페이지 너비 보기와 큰 PDF의 HTTP Range 스트리밍, HTML의 상대 이미지·CSS,
코드 문법 색상, Markdown 렌더링·원문 전환을 지원합니다. Markdown 출력은 정제하고
사용자 HTML/SVG의 스크립트·내장 프레임은 차단합니다. 선택한 루트 밖의 심볼릭 링크와
상위 경로 접근을 차단하며 숨김 파일은 기본으로 제외합니다.

자동 줄바꿈은 기본 켜짐입니다. 접힌 긴 줄에도 원래 논리 줄번호를 유지하며, 30만 자를 넘는
텍스트는 문법 색상·Markdown 서식 없이 원문으로 표시하고 2만 논리 줄을 넘으면 줄번호를 생략합니다.
세로 분할선으로 목록 너비를 조절하고 크게 보기는 웹 페이지 안에서만 동작합니다. Escape로 복귀합니다.

### 파일 탭·두 창 비교·미리보기 너비 (0.6.0)

파일을 열면 루트 이름과 상대 경로를 표시한 탭이 생깁니다. 같은 루트·경로를 다시 선택하면 기존 탭을
활성화하며, 다른 루트의 같은 이름은 별도 탭으로 구분합니다. 다른 파일·루트를 고르거나 Git diff를
열어도 기존 편집기는 탭에 남습니다. 탭의 **×**로 닫고 필요 없는 탭은 닫아 메모리를 돌려주세요.
열린 탭마다 문서와 편집기를 메모리에 유지하므로 큰 파일을 많이 열면 메모리 사용량이 늘어납니다.
0.9.0부터 편집기 그룹을 반복해서 나누어 여러 문서를 동시에 볼 수 있습니다. 미리보기 위의 별도 도구 행은 없으며 탭 표시줄부터 문서가 시작합니다.

탭을 **대상 그룹**의 왼쪽·오른쪽 가장자리로 끌면 그 그룹만 좌우로, 위·아래 가장자리로 끌면 그 그룹만 상하로 나눕니다.
이미 나눈 그룹도 다시 나눌 수 있어 2×2나 비대칭 배치를 만들 수 있습니다.
0.9.1부터 트리·검색 결과의 파일 이름이나 아이콘도 그룹 가장자리·가운데·탭 표시줄로 끌어 열 수 있습니다.
드래그는 파일 내용을 옮기거나 복사하지 않습니다. 이미 열린 파일은 기존 탭·초안을 유지한 채 이동합니다.
포인터를 따라가는 파일 표시와 탭 삽입선을 확인한 뒤 놓고, Escape나 창 밖에 놓기로 취소합니다.
탭 표시줄에 놓으면 탭 순서와 소속 창을 바꾸고, 다른 창 가운데에 놓으면 그 창으로 이동합니다.
마지막 탭을 옮기거나 닫은 그룹은 바로 옆의 같은 분할에 속한 그룹과 합쳐지고 다른 그룹의 배치는 유지합니다. 새 파일은 현재 포커스가 있는 그룹에 열립니다.
탭 버튼에서 방향키·Home·End로 탭을 선택하고 Delete로 닫습니다. 각 그룹 사이 분할선은 드래그하거나
포커스를 둔 뒤 방향키로 조절합니다. Shift+방향키는 크게 조절하고 Home·End는 해당 분할의 최소·최대 크기로 맞춥니다. 브라우저 창 크기를 바꾸면 각 그룹과 줄바꿈이 새 너비에 맞춰집니다.
Ctrl/Cmd+S는 포커스가 있는 창의 파일만 저장합니다. 목록 분할선·크게 보기·Escape 복귀도 사용할 수 있습니다.
크게 보기에서는 모든 탭 표시줄을 숨기고 문서를 화면 맨 위부터 표시합니다. Escape나 작은 복귀 버튼으로 전체 그룹 배치·비율·활성 탭을 복원합니다.

Markdown은 0.9.0부터 기본으로 **현재 그룹 전체 너비**를 사용합니다. **읽기 너비** 버튼으로
가운데 읽기 너비(최대 약 1000px)를 선택할 수 있으며 명시적으로 고른 너비는 다음에도 기억합니다.
HTML의 기본값은 읽기 너비이며 **전체 너비** 버튼으로 전체 너비를 선택합니다. Markdown과 HTML의 선택은 따로 기억합니다. 창 크기를 바꾸면 바로 반영하며 HTML 문서 자체의 CSS 너비 제한은 유지합니다.
PDF는 기존 페이지 너비 맞춤을 사용합니다. 너비 선택은 브라우저에 작은 설정값만 저장합니다.
파일 내용·초안·선택 위치·실행 취소 기록이나 열린 파일 목록은 저장하지 않으며 페이지를 다시 열면 복구하지 않습니다.

### 파일 복사·붙여넣기와 선택한 창 크게 보기

파일 트리에서 파일 또는 폴더 하나를 선택하고 **Ctrl/Cmd+C**, 대상 폴더에서 **Ctrl/Cmd+V**를 누르거나
오른쪽 클릭 메뉴의 **Copy / Paste**를 사용합니다. 폴더를 선택하면 그 안에, 파일을 선택하면 그 파일의
상위 폴더에 붙여넣습니다. 트리의 빈 공간은 현재 루트를 대상으로 합니다. 같은 앱에 등록한 다른 루트로도
복사할 수 있습니다. 기존 이름이 있으면 확장자를 유지한 새 이름을 자동 선택하며 덮어쓰거나 폴더를 합치지 않습니다.

Copy는 루트·경로·디스크 버전만 메모리에 기억합니다. 붙여넣기는 저장된 디스크 내용을 복사하며 열린
편집기의 저장 전 초안은 복사하지 않습니다. Copy 이후 원본이 변경·삭제되거나 루트 연결 경계가 바뀌면
붙여넣기를 거절하므로 다시 Copy하세요. 폴더의 버전 확인은 폴더 자체를 대상으로 하며, 하위 파일은 붙여넣을 때의 저장 내용을 복사합니다. 앱을 다시 열면 파일 복사 선택은 사라집니다. 원문 편집기·검색창·
입력란의 Ctrl/Cmd+C/V는 텍스트 복사·붙여넣기로 동작합니다. **Copy Path / Copy Relative Path**는 별도 기능입니다.

탭 이름을 대상 그룹의 가장자리로 끌면 분할 위치를 미리 표시합니다. Escape·영역 밖 이동으로 드래그를 취소할 수 있습니다.
탭 또는 그룹 표시줄을 오른쪽 클릭하거나 탭에서 **Shift+F10**을 눌러 **크게 보기**를 선택하면 해당
문서만 페이지 안에서 커지고 다른 그룹은 숨겨집니다. Escape 또는 작은 복귀 버튼으로 돌아오면 이전 그룹 배치와
분할 비율을 복원합니다. 문서·초안·실행 취소 기록은 그대로 유지하며 브라우저 전체 화면을 요청하지 않습니다.

### 파일·폴더 작업 (0.7.0)

파일 트리의 폴더를 오른쪽 클릭해 **New File**을 선택합니다. 파일을 오른쪽 클릭하면 그 파일의 상위
폴더에 만들고, 트리의 빈 공간이나 왼쪽 **새 파일…** 버튼은 선택한 루트에 만듭니다. 트리 항목에
포커스를 둔 상태에서 Shift+F10 또는 ContextMenu 키로도 메뉴를 열 수 있습니다. 대화상자의 루트·폴더
대상을 확인하고 파일 이름 하나를 입력하세요. 한글·공백·따옴표를 지원하며 경로 구분자·상위 경로는
허용하지 않습니다. 기존 이름이 있으면 덮어쓰지 않고 이름과 오류를 그대로 표시합니다.

빈 파일이 만들어지면 Markdown·HTML을 포함해 편집 가능한 원문에 바로 포커스를 둡니다. 입력 후
저장해야 실제 내용이 기록됩니다. 이후 직접 선택한 원문/미리보기 모드는 다음 열기에도 적용합니다.
제출 전에 취소하면 파일을 만들지 않습니다. 제출 후에는 완료될 때까지 취소·Escape와 파일 이름 변경을
잠시 막습니다. 요청 중 선택한 루트나 탭이 바뀌면 완료 결과가 현재 편집기를 바꾸지 않으며 안내된 대상에서 확인합니다. Git 저장소에 속하고 무시 규칙에 해당하지 않는 새 파일은 미추적 파일로 표시합니다. Git 동작은 초안을 자동 저장하지 않습니다.
등록 루트 안의 실제 쓰기 가능한 폴더만 허용하며 심볼릭 링크를 거치는 생성은 거절합니다.

오른쪽 클릭 메뉴는 **New File / New Folder / Copy Path / Copy Relative Path / Duplicate / Rename / Delete**를 제공합니다.
새 폴더도 클릭한 폴더 안에 만들며, 파일을 클릭하면 그 파일의 상위 폴더에 만듭니다. 빈 공간에서는
현재 루트에 만듭니다. 경로 복사는 서버의 절대 경로를, 상대 경로 복사는 선택한 등록 루트를 기준으로 한
경로를 복사합니다. 루트 자체의 이름 변경·복제·삭제는 허용하지 않습니다.

복제는 같은 폴더에 충돌하지 않는 새 이름을 골라 디스크에 저장된 바이트를 복사합니다. 파일 확장자를
유지하며 편집기의 저장 전 초안은 복제하지 않습니다. 폴더 복제는 숨겨진 자식도 포함하며, 심볼릭 링크는
링크 자체를 복사하고 링크 대상을 따라 복사하지 않습니다. 큰 파일·폴더는 크기에 비례한 디스크 읽기·쓰기와
추가 공간이 필요합니다. 재귀 작업은 최대 50,000개 항목·128단계로 제한합니다. 실패한 작업의 오류를 확인하고
디스크 상태를 확인한 뒤 다시 시도하세요. 일부 변경이 이미 적용됐거나 응답이 끊긴 경우에는 그 사실을 안내합니다.
복제와 폴더 삭제 중에는 다른 파일을 계속 볼 수 있습니다. **Hide progress**로 진행 표시를 숨기고
진행 버튼으로 다시 열 수 있으며, 숨기기는 작업을 취소하거나 다시 실행하지 않습니다. 한 번에 하나의
파일 작업을 제출합니다. 같은 루트의 디스크 변경은 순서대로 처리하므로 큰 복제가 저장을 지연시킬 수
있습니다. 응답 대기는 복제 30분·폴더 삭제 10분·이름 변경과 폴더 생성 30초이며, 시간 초과는 작업
취소를 보장하지 않습니다. 별도 백그라운드 작업 관리 기능은 제공하지 않습니다.

이름 변경에는 경로가 아닌 새 이름 하나를 입력합니다. 기존 항목을 덮어쓰지 않습니다. 열린 파일이나
폴더 안의 열린 자식은 새 경로를 따르며, 저장 전 초안·선택 위치·실행 취소 기록을 유지합니다. 그 뒤 저장은
새 경로에만 기록합니다. 외부 변경으로 원래 편집 내용과의 연결을 확인할 수 없으면 충돌을 표시하고 저장을
막습니다. 초안을 복사해 보관하거나 디스크에서 다시 불러오세요. 작업 중인 저장이 끝난 뒤 이름 변경을
다시 시도해야 할 수 있습니다. 확장자가 달라지면 원문 언어와 미리보기 종류도 새 이름을 따릅니다.

**실제 삭제는 항상 이름과 서버 경로를 보여 주고 정말 삭제할지 확인합니다.** 폴더는 내부 내용도 함께
삭제한다는 안내를 포함합니다. 영향받는 열린 초안이 있으면 같은 확인에 초안 손실 경고를 표시합니다.
취소하면 삭제 요청을 보내지 않으며 파일을 변경하지 않습니다. 확인하면 디스크에서 영구 삭제하고 해당 파일·
폴더 내부의 탭만 닫습니다. 휴지통·복구 기능은 제공하지 않습니다. 심볼릭 링크를 삭제하면 링크만 삭제하며
대상은 유지합니다. 쓰기 동작은 서버 계정의 파일시스템 권한, 등록 루트 경계와 숨김·제외 규칙을 적용합니다.
생성은 심볼릭 링크를 거치는 폴더에 허용하지 않습니다.

### 원문 편집과 저장 (0.6.0)

텍스트·코드·LaTeX 파일을 열면 기존 원문 영역에서 바로 입력합니다. 별도의 편집 버튼은 없습니다.
**저장** 또는 **Ctrl+S / Cmd+S**로 현재 파일을 저장하고, **Ctrl+Z / Cmd+Z**로 실행 취소,
**Ctrl+Shift+Z / Cmd+Shift+Z**로 다시 실행합니다. 저장하거나 원문·미리보기를 전환해도 현재 편집기의
실행 취소 기록은 유지됩니다. 수정 표시는 마지막 저장 내용과 다를 때 나타나며 자동 저장은 하지 않습니다.

Markdown·HTML은 처음에 미리보기를 표시합니다. **원문 보기 / 미리보기**로 전환하면 저장 전 수정 내용도
미리보기에 반영합니다. HTML 미리보기의 상대 CSS·이미지는 원래 파일 위치를 기준으로 읽고 스크립트는
차단합니다. 미리보기는 전환할 때 갱신합니다. 마지막으로 고른 탭은 프로젝트·등록 루트·파일별로
XDG 설정에 보관하여 브라우저나 서버를 다시 열어도 기억합니다. 최근 파일 수에 따른 삭제나
브라우저 localStorage 용량 제한은 없으며 파일을 열거나 탭을 고를 때 해당 기록만 읽고 씁니다.
이 설정은 탭 선택만 저장합니다. 저장 전 초안과 실행 취소 기록은 브라우저를 닫은 뒤 복구하지 않습니다.

다른 파일을 열거나 루트를 고르면 기존 파일은 탭에 남아 초안·선택 위치·스크롤·실행 취소 기록을 유지합니다.
수정한 탭을 닫거나 현재 파일을 새로고침할 때, 해당 루트의 경로를 바꾸거나 연결을 제거할 때 확인합니다.
취소하면 초안과 선택 위치를 유지합니다. 브라우저 창을 닫거나 페이지를 떠날 때는 브라우저의 변경사항 경고를 사용합니다.
외부에서 파일이 바뀐 경우 저장을 거절하고 충돌을 알립니다. 저장 오류가 나면 수정 내용은 편집기에
남으므로 복사하거나 **디스크에서 다시 불러오기**를 선택할 수 있습니다. 다시 불러오거나 변경을 버리는
이동을 확인하면 현재 초안과 실행 취소 기록은 사라집니다.

편집은 기존 일반 파일에 한정하며 다음 제한을 적용합니다.

- 유효한 UTF-8(선택적 BOM), BOM이 있는 UTF-16LE/BE·UTF-32LE/BE를 지원합니다.
  원래 인코딩과 BOM, 일관된 LF·CRLF·CR 줄바꿈을 저장할 때 유지합니다. 화면 안에서는 LF로 편집합니다.
- 서로 다른 줄바꿈이 섞인 파일, 하드 링크, 심볼릭 링크 및 심볼릭 링크를 거치는 경로,
  쓰기 권한이 없는 파일은 읽기 전용입니다. 이유를 표시하며 저장을 허용하지 않습니다.
- 원본은 **8 MiB(8,388,608바이트) 이하**여야 합니다. 저장 요청의 UTF-8 텍스트와 원래 인코딩으로
  변환한 최종 파일도 각각 이 한도를 넘을 수 없습니다. 초과하면 저장을 거절합니다.
- 지원하지 않는 인코딩, 바이너리 제어 문자가 있는 파일, 8 MiB를 넘는 파일은 편집을 허용하지 않습니다.
  읽기 전용 원문 또는 오류 안내에 이유를 표시하며 원본 링크와 기존 파일 제공 경로를 이용할 수 있습니다.
- 파일 생성·폴더 생성·복제·이름 변경·삭제와 저장은 인증된 같은 출처 요청에서만 허용하며,
  등록 루트 경계와 파일 버전을 확인합니다. 저장은 임시 파일을 원자적으로 교체합니다.

### Python·LaTeX 현재 파일 검사

편집 가능한 Python(`.py`, `.pyw`)과 LaTeX(`.tex`, `.sty`, `.cls`) 원문은 입력을 약 800ms 멈추면
저장 전 현재 내용을 검사합니다. 현재 선택한 루트의 활성 탭 하나만 검사하며 다른 그룹·백그라운드 탭은
검사하지 않습니다. 오류 범위는 빨간 물결 밑줄, 경고 범위는 노란 물결 밑줄로 표시하며 마우스를 올리면
검사 코드와 메시지를 확인할 수 있습니다. 같은 범위의 오류·경고는 오류 밑줄을 우선 표시하고 메시지는 함께 보여 줍니다.
줄번호 옆 표시와 **문제** 목록도 유지됩니다. **문제**를 누르면 버튼 가까이에 크기가 제한된 목록이 떠서
코드 영역을 밀어내지 않으며, 긴 목록은 내부에서 스크롤합니다. 항목을 누르면 해당 줄·열로 이동하고 목록이 닫힙니다.
바깥 클릭·Esc·닫기 버튼으로도 닫을 수 있습니다. **검사 켜짐/꺼짐**으로 검사를 중지하거나 다시 켜고 **재검사**로 직접 요청할 수 있습니다.
검사 설정은 이 서버 주소의 브라우저 저장소에 기억하며, 입력 중인 조합 문자가 확정될 때까지 기다립니다.

서버의 선택적 외부 도구 **Ruff**(Python), **ChkTeX**(LaTeX)가 필요합니다. 실행 PATH에서 찾거나
서버 시작 전에 `FBROWSE_RUFF=/절대/경로/ruff`, `FBROWSE_CHKTEX=/절대/경로/chktex`로 지정합니다.
도구가 없으면 간단한 사용 불가 상태를 표시하고 편집·저장은 계속 사용할 수 있습니다. 앱은 도구를 자동 설치하지 않습니다.
Ruff의 구문·기본 오류·일부 버그 규칙과 ChkTeX의 구조·표기 검사를 사용합니다. Python 타입 분석이나
전체 TeX 컴파일·참조 검증은 제공하지 않으며 발견된 문제가 없다는 표시는 문서 전체의 정확성을 보증하지 않습니다.

검사는 현재 텍스트를 표준 입력으로만 전달하며 Python·TeX 코드를 실행하거나 프로젝트 설정·포함 파일을
읽지 않습니다. 중립 임시 디렉터리에서 실행하고 프로젝트에 `.pyc`, `.aux`, 캐시나 수정 파일을 만들지 않습니다.
검사할 UTF-8 텍스트는 **512 KiB**, 결과는 **200개**, 검사기 출력은 **256 KiB**, 도구 실행은 **3초**로
제한합니다. 서버 전체에서 동시에 2개 실행·4개 대기하며 한도를 넘으면 재검사 가능한 상태를 표시합니다.
파일·루트·버전 또는 활성 탭이 바뀐 뒤 도착한 결과는 적용하지 않으며 주기적인 폴링·자동 저장·자동 수정은 없습니다.

Markdown 코드 블록의 언어 표시와 **COPY** 버튼은 블록 **왼쪽 위**에 있습니다. 버튼은 해당 코드의
공백·줄바꿈·Unicode를 그대로 복사하며 원문이나 붙여넣기 동작을 바꾸지 않습니다.

Markdown 수식은 KaTeX로 렌더링합니다. [수식 예제](examples/markdown-math.md)를 미리보기로 열어 확인할 수 있습니다.

| 문법 | 표시 |
| --- | --- |
| `$E=mc^2$`, `\(E=mc^2\)` | 문장 안의 수식 |
| `$$ ... $$`, `\[ ... \]` | 별도 줄의 수식 (여러 줄 가능) |
| `\begin{equation} ... \end{equation}` | 독립 수식 |
| `\begin{align} ... \end{align}` | 정렬한 여러 줄 수식 |
| `gather`, `alignat` 환경 | 여러 줄·열 수식 |
| 언어를 `math`로 지정한 코드 울타리 | 별도 줄의 수식 |

위 환경은 `equation*`, `align*`처럼 별표가 붙은 형태도 지원합니다. 행렬·분수·합·적분 등은
수식 구분자 안에 LaTeX 문법으로 작성합니다. 지원 명령은 [KaTeX 공식 목록](https://katex.org/docs/supported.html)을
따르며 완전한 LaTeX 문서 컴파일이나 문서 전체 자동 수식 번호·참조는 제공하지 않습니다.
일반 코드 울타리와 인라인 코드는 수식으로 바꾸지 않습니다. 가격 `$5 and $10`, 이스케이프한
`\$` 및 닫히지 않은 구분자는 텍스트로 유지합니다. `$ ... $`처럼 달러 바로 안쪽에 공백을 넣으면
일반 텍스트로 취급하므로 `$x + y$`처럼 작성하세요.

잘못된 수식은 해당 수식의 원문과 안내를 표시하고 나머지 문서는 계속 렌더링합니다.
한 문서에서 최대 1,000개, 개별 수식 2만 자까지 렌더링하며 그 이상은 수식 원문을 표시합니다.
수식의 외부 이미지·링크·사용자 HTML 명령은 허용하지 않습니다. 원문 보기와 복사는 원래 텍스트를 유지합니다.
KaTeX의 JS·CSS·폰트는 npm 설치에 포함되어 수식 렌더링 자체에는 네트워크가 필요하지 않습니다.

PDF.js와 코드/Markdown 구성 요소는 고정 버전과 SHA-256 검증을 거쳐
`$XDG_CACHE_HOME/project-file-browser`에 캐시합니다. 최초 준비에는 네트워크가 필요하고,
캐시가 준비되면 오프라인으로 사용할 수 있습니다. 기존 코드/Markdown 캐시는 재사용합니다.
Python 버전의 PDF.js 캐시에 파일별 검증 정보가 없으면 Node 전용 `pdfjs-6.4.299-node`에
한 번 새로 준비합니다. 실행 중인 기존 뷰어의 캐시는 덮어쓰지 않습니다.
PDF.js 준비가 실패하면 브라우저 기본 PDF 뷰어로 전환합니다.

## 업데이트와 제거

```bash
npm install --global @wlalsrne/fbrowse@latest
fbrowse restart /path/to/project
npm uninstall --global @wlalsrne/fbrowse
```

`--prefix`로 설치했다면 업데이트·제거 때도 같은 prefix를 지정합니다. 업데이트 자체는 실행 중인
서버를 종료하지 않습니다. 새 코드를 적용할 프로젝트만 명시적으로 재시작하세요.
제거 전에 필요한 프로젝트의 `fbrowse stop`을 실행하세요. npm 제거는 실행 중인 서버를 강제로
종료하거나 XDG 설정·상태·캐시 및 프로젝트 데이터를 삭제하는 명령이 아닙니다.

Node 실행 상태와 로그는 `$XDG_STATE_HOME/fbrowse/<경로 해시>/`에 저장합니다.
이전 Python 버전의 상태 위치와 분리되어 있으며 Node 명령은 tmux 세션을 조작하지 않습니다.

## Git 상태와 변경 보기

서버에 `git`이 있으면 선택한 루트의 저장소 상태를 조회할 수 있습니다. Git이 없는 서버와
일반 디스크 폴더도 기존처럼 파일 탐색·미리보기를 사용할 수 있습니다. npm Git 라이브러리나
계정 연결은 필요하지 않습니다.

파일 이름에 색상과 상태를 표시합니다: `M` 수정, `U` 미추적, `A` 추가, `D` 삭제,
`R` 이름 변경, `T` 유형 변경, `!` 충돌. 상위 폴더에는 하위 파일의 변경 상태를 요약합니다.
왼쪽 Git 보기에서는 브랜치와 스테이징된 변경·작업 중 변경·미추적 파일을 구분하고,
파일을 선택하면 오른쪽에서 추가·삭제 줄을 구분한 diff 또는 새 파일의 내용을 볼 수 있습니다.
diff 왼쪽에는 원본·변경 후 줄번호를 나란히 표시합니다. 삭제 줄에는 원본 번호, 추가 줄에는 변경 후
번호가 나오며 중간에 생략된 구간이 있어도 실제 파일의 줄번호를 사용합니다. 자동 줄바꿈은 기본 켜짐이며
이어진 줄에는 번호를 추가하지 않습니다. 줄바꿈을 끄면 가로로 스크롤해도 줄번호가 왼쪽에 유지됩니다.
바이너리·큰 파일·변경 없음·조회 실패는 안내로 표시합니다.
diff 응답은 최대 1MiB, 화면은 최대 2만 줄까지 표시하며 미추적 파일 내용은 최대 128KiB입니다.
전체 파일은 기존 파일 미리보기를 이용하세요. Git 조회는 약 5초 안에 끝나지 않으면 안내로 전환합니다.

조회는 선택한 루트만 대상으로 하며 결과를 약 2초 캐시합니다. 새로고침은 Git 상태도 갱신합니다.
주기적인 전체 저장소 스캔과 네트워크 요청은 하지 않습니다. 저장소의 하위 폴더를 루트로
연결한 경우 그 폴더 안의 경로만 표시합니다. 숨김·제외 파일 규칙과 루트 ID 구분도 동일하게 적용합니다.
파일 상태·diff의 자동 조회에는 외부 Git 도우미·변환 필터·전역 Git 설정을 적용하지 않습니다. 저장소의 `.gitignore`는 적용하며,
전역 ignore 설정이나 LFS 같은 변환 필터를 사용하는 저장소는 일반 Git과 표시가 다를 수 있습니다.
변환 필터가 설정되어 있으면 Git 보기에 안내하며 diff는 저장된 원문 기준으로 비교합니다.

### 스테이징·커밋·push와 기록

Git 보기의 변경 목록에서 파일 옆 버튼으로 **스테이징 / 스테이징 해제**합니다. 커밋 메시지를
입력하고 **커밋**하면 현재 스테이징된 파일만 커밋합니다. 파일 편집이나 자동 스테이징은 하지 않습니다.
**push**는 서버에 이미 설정된 remote와 현재 브랜치의 목적지를 보여준 뒤 확인 버튼을 눌러야 실행합니다.
강제 push, 전체 브랜치 push, 원격 삭제는 제공하지 않습니다. 연결 계정을 별도로 만들지 않으며
서버 Git의 기존 사용자 이름·이메일과 인증 설정을 사용합니다. 인증이나 Git 설정이 필요하면
터미널에서 먼저 설정하세요. 비밀번호 입력창을 무한 대기하지 않으며, 실패 내용을 확인하고 직접 재시도할 수 있습니다.

**브랜치 / 기록**에서는 로컬·원격 추적 브랜치와 커밋 이력을 필요할 때 페이지 단위로 조회합니다.
브랜치 전환·생성·삭제, pull·fetch·reset·rebase는 수행하지 않습니다. 원격 추적 목록은 서버에
이미 저장된 정보이며, 화면을 열거나 새로고침해도 원격 저장소에 접속하지 않습니다.

쓰기 동작은 선택한 루트가 Git 저장소 최상위 폴더일 때만 가능합니다. 저장소 하위 폴더를 루트로
연결하면 조회만 할 수 있습니다. 화면을 연 뒤 HEAD·브랜치·스테이징 상태가 바뀌면 작업을 거절하고
다시 조회하게 합니다. 변경 목록이 표시 한도를 넘으면 커밋 버튼을 비활성화합니다. 숨김·제외 파일이 스테이징되어 있거나 충돌·병합 진행 상태·분리된 HEAD가 있으면
커밋을 막고 이유를 표시합니다. `--show-hidden`으로 시작하면 숨김 파일도 명시적으로 다룰 수 있습니다.
커밋은 Git index 전체를 대상으로 하므로 커밋 전에 표시된 스테이징 목록을 확인하세요.

사용자가 직접 요청하는 쓰기 동작은 Git의 기존 설정·hooks·필터를 적용합니다. 따라서 저장소에
설정된 hook이나 변환 도구가 실행될 수 있습니다. 로컬 작업은 30초, push는 60초 제한을 두며,
시간 초과 뒤에는 자동 재시도하지 않습니다. 터미널의 Git 상태·원격 기록을 확인한 뒤 재시도하세요.
원격 인증이 없는 환경에서는 조회·스테이징·로컬 커밋을 계속 사용할 수 있습니다.

심볼릭 링크는 `↗` 표시와 마우스 오버의 대상 경로로 구분합니다. 루트 안의 링크는 파일과 폴더를
열 수 있고, 끊긴 링크·루트 밖 링크는 비활성화된 항목으로 표시합니다. 루트 밖의 폴더가 필요하면
해당 폴더를 별도 루트로 연결하세요. 링크로 검색 경계를 넓히거나 디렉터리 링크를 재귀 검색하지 않습니다.
Git 상태와 diff는 링크 자체의 경로와 링크 대상 문자열을 기준으로 하며, 대상 파일의 상태와 혼동하지 않습니다.

## 개발과 검증

```bash
npm ci
npm test
npm run pack:check
FBROWSE_PLAYWRIGHT_MODULE=/path/to/playwright npm run test:browser
```

테스트는 임시 HOME/XDG/프로젝트를 사용합니다. 패키지 검증은 실제 npm 압축을 임시 전역 경로에 설치하고,
PATH에 Node만 남긴 환경에서 실행하여 Python·Bash·tmux·flock 없이 동작하는지 확인합니다.
Playwright와 Chromium은 선택적 개발 도구이며 앱 실행에는 필요하지 않습니다.
진단 브라우저 검증에는 실제 Ruff·ChkTeX가 필요합니다. `FBROWSE_RUFF`, `FBROWSE_CHKTEX` 절대 경로를 지정할 수 있고,
`FBROWSE_REQUIRE_REAL_DIAGNOSTICS=1 npm test`로 HTTP 검증에서도 도구 누락을 실패로 처리합니다.

## npm 배포 (관리자)

패키지는 npm 계정 `wlalsrne`의 `@wlalsrne/fbrowse` 이름으로 공개 배포합니다.
배포 전에 변경 내용을 검증하고 새 버전을 지정하세요. 이미 게시한 버전은 덮어쓸 수 없습니다.
`package.json`과 `package-lock.json`의 버전을 함께 갱신하고 CLI·서버 버전도 맞춥니다.
다음은 0.9.1 배포 명령의 예입니다.

```bash
npm whoami
npm test
npm pack --pack-destination dist
npm publish ./dist/wlalsrne-fbrowse-0.9.1.tgz --access public
```

`npm pack`으로 만든 앱 코드·문서만 게시합니다. 프로젝트 데이터, XDG 설정·상태·캐시와
개발용 테스트·인증 파일은 포함하지 않습니다. 게시할 때 npm의 2단계 인증을 완료해야 할 수 있습니다.
배포 후 임시 전역 경로에 레지스트리의 패키지를 설치해 `fbrowse --version`과 실행을 확인하세요.
